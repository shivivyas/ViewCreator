🗄️ Epic 1: Database Safety & Migrations

1.1 Destructive schema.sql → versioned migrations viewcreator-database
Problem: schema.sql uses DROP TABLE IF EXISTS — every migration wipes all data. This is the #1 risk for any staging/prod deployment.
  • Replace schema.sql with node-pg-migrate
    Each table gets its own timestamped up/down migration file. Current schema becomes migrations/001-initial.sql (CREATE IF NOT EXISTS — no DROP).
    viewcreator-database/src/schema.sql viewcreator-database/src/migrate.ts viewcreator-database/package.json
    P0
  • Add migration runner to npm scripts
    npm run db:migrate runs pending migrations sequentially. npm run db:rollback reverts last. Seed stays independent.
    viewcreator-database/package.json
    P0
1.2 Add database indexes for query performance viewcreator-database
Problem: credit_transactions and user_creations already have composite indexes, but users(email) is the only single-column index. Add missing indexes for foreign key lookups.
  • Add FK indexes for all join columns
    Index user_subscriptions(user_id), user_subscriptions(plan_id), user_credits(user_id), user_creations(user_id) — some may already exist but verify.
    viewcreator-database/src/schema.sql
    P1

🛡️ Epic 2: Input Validation & Error Handling

2.1 Add Zod for request body validation viewcreator-api
Problem: All 12+ API routes validate inputs manually (if (!title), if (!prompt)). No type-safe schema enforcement. Error responses are inconsistent — some return { error }, others { errors }.
  • Install zod, create shared validation schemas
    Schemas for: generateSchema, editImageSchema, uploadTemplateSchema, createCheckoutSchema. Place in viewcreator-shared/src/validation/ or viewcreator-api/src/validation/.
    viewcreator-api/package.json viewcreator-api/src/middleware/
    P1
  • Create validate(schema) middleware
    Express middleware that parses req.body against a Zod schema, returns 400 with { error, details } on mismatch. Apply to all POST/PUT endpoints.
    viewcreator-api/src/middleware/validate.ts
    P1
  • Unify error response format
    All endpoints return { error: string, details?: any } on failure. 402 errors include { credits_balance, required, upgrade_url } — keep this pattern, extend to all error paths.
    viewcreator-api/src/index.ts viewcreator-api/src/routes/payments.ts
    P1

🎯 Epic 6: UX Papercuts

6.1 Fix pre-existing TS errors viewcreator-ui
Problem: payments/history/page.tsx has 3 TypeScript errors (lines 31, 33). The page compiles but has broken runtime behavior for the transaction history feature.
  • Fix transaction history page
    The getTransactions().then() callback has an incorrect type signature returning "" instead of the expected type. Fix the promise chain.
    viewcreator-ui/src/app/payments/history/page.tsx
    P0
6.2 Auth proxy covers all protected routes viewcreator-ui
Problem: proxy.ts only protects /generate/edit. But /generate, /templates (upload), and /payments/* also require auth for key features. Currently, auth is checked client-side per-action, which means unauthenticated users can reach the page before being blocked.
  • Extend proxy.ts route matcher
    Protect /generate(.*), /payments(.*) at the proxy level. Keep /templates public (browsing is OK, upload requires auth).
    viewcreator-ui/src/proxy.ts
    P1
6.3 Templates cache invalidation on upload viewcreator-ui
Problem: Template list is cached in-memory with a 30s TTL. After upload, the cache is cleared and refetch is forced — but the 30s Cache-Control header on the API response means the browser/CDN may serve stale data within that window.
  • Bypass browser cache on mutation
    After upload/delete/vote, call fetchTemplates(true) with a cache-busting query param (?_t=Date.now()) to bypass the 30s Cache-Control.
    viewcreator-ui/src/services/api/template-service.ts viewcreator-ui/src/app/templates/page.tsx
    P1
