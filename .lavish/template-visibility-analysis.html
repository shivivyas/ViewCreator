🧩 Template Visibility — Problem Analysis

Why guests see user-uploaded templates, and how to fix it

🎯 The Problem

User uploads a template → signs out → guests see it. This shouldn't happen. User-uploaded templates (even when marked "public") are showing up for guests who never signed in.

👤 User uploads template → Toggle = Public → user_id = NULL → 👻 Guest sees it

🔍 Current Architecture

Upload Flow

FieldFrontendBackendDB
isPublic: true Default Sets user_id = null t.user_id IS NULL
isPublic: false User opt-in Sets user_id = userId t.user_id = 'user_xxx'

Guest Query (VoteRepository.findAllWithVotes)

WHERE (t.user_id IS NULL OR t.user_id = $1)

For guests: $1 = null → t.user_id = null is always FALSE in SQL. But t.user_id IS NULL matches ALL public templates — including user uploads.

📊 What's in the Database

Typeuser_idVisible to Guests?Source
Seeded templates NULL ✅ Yes seed.ts — intentionally public
User uploads (public) NULL ✅ Yes (bug) Frontend defaults to public
User uploads (private) user_xxx ❌ No User explicitly toggled to private

The problem: seeded templates and user-uploaded public templates are indistinguishable in the DB. Both have user_id = NULL.

💡 Possible Solutions

Option A: Add is_featured column Recommended

Add a boolean column is_featured to the templates table. Seeded templates get true; user uploads get false. The guest query filters for is_featured = true instead of user_id IS NULL.

WHERE (t.is_featured = true OR t.user_id = $1)
  • ✅ Clean separation: seeded vs user-uploaded are distinguishable
  • ✅ Seeded templates are always world-visible
  • ✅ User uploads (public or private) only visible to signed-in users
  • ✅ Easy to promote user templates to featured later
  • ⚠️ Requires a DB migration + updating seed.ts

Option B: Filter by user_id IS NULL AND config->>'source' = 'seed'

Use the existing config JSONB column to tag seeded templates. No schema migration needed — just update the seed script to set config.source = 'seed'.

WHERE (t.config->>'source' = 'seed' OR t.user_id = $1)
  • ✅ No DB migration — just update seed.ts
  • ✅ Leverages existing JSONB column
  • ⚠️ Slightly slower query (JSONB access vs direct column)
  • ⚠️ Less explicit — relies on convention

Option C: Dual query — signed-in sees all, guest sees only seeded

Use a hardcoded list of seeded template IDs in the query for guests. No schema changes.

-- Guest: return only pre-seeded template IDs
WHERE t.id IN ('uuid-1', 'uuid-2', ...)
  • ✅ Simplest implementation (no migration)
  • ⚠️ Brittle — adding new seeded templates requires code change
  • ⚠️ Doesn't scale — what if admins want to feature templates later?

Option D: What you originally tried — flip default to private

Change isPublic default from true → false. User uploads stay private unless explicitly shared.

  • ✅ Simplest change (1 line)
  • ⚠️ Contradicts your stated preference (default should be public)
  • ⚠️ Changes the UX: users must opt-in to share templates
