9

Header badge — real-time update after generation?

User generates an image. Does the "100 credits" badge update immediately?

✅ Decision: From API response (option b)

The generate endpoint returns { balance_after, credits_deducted }. The frontend updates the header badge synchronously from the response — no polling needed, instant update, zero extra requests. This is the most efficient + real-time approach for in-page actions.

Edge Cases & Race Conditions

12

Two-tab race condition — 1 credit, both tabs click Generate

✅ Decision: First wins, second fails (option a)

Tab 1 gets image, Tab 2 gets 402 → credit gate modal. Row-level locking (SELECT...FOR UPDATE) ensures atomicity. Test: verify Tab 2 shows gate.

13

Premium + insufficient — 1 credit, click Premium (costs 2)

What happens when user selects Premium but doesn't have enough credits?

✅ Decision: Credit gate modal (option a)

"You have 1 credit but need 2" — buy CTA in the modal. Same gate component, dynamic messaging based on shortfall amount.

14

Concurrent webhook + manual purchase — double credit grant?

✅ Decision: Idempotent (option a)

webhook_events table with event_id prevents double-grant. First path (webhook or confirm-purchase) writes event_id, second path sees it exists and skips. Test: replay webhook event, verify no extra credits.
