🛠️ Admin Dashboard — Build vs Use Strategy

For a micro-SaaS: what to build, what to use off-the-shelf, and why

🎯 First Principle

Don't build what you already have. ViewCreator already uses three SaaS tools that each provide admin capabilities out of the box. Building a custom admin dashboard that duplicates their functionality is wasted effort. The right approach is:

✅ Use existing dashboards → 🔧 Build only app-specific needs → 📈 Add lightweight monitoring

📦 What You Already Have (Free)

🔐 Clerk Dashboard

clerk.com — already configured

  • ✅ All users — list, search, view details
  • ✅ User management — ban, delete, impersonate
  • ✅ Sessions & devices — active sessions per user
  • ✅ Webhook logs — delivery history
  • ✅ Audit log — every sign-in, sign-up, update
  • ✅ Analytics — MAU, sign-ups, active sessions

💳 Dodo Payments Dashboard

app.dodopayments.com — already configured

  • ✅ All transactions — payments, refunds, disputes
  • ✅ Customer list — email, purchase history
  • ✅ Subscription management — active, cancelled, past due
  • ✅ Revenue reporting — MRR, ARR, churn
  • ✅ Webhook logs — delivery attempts, failures
  • ✅ Refunds & disputes — process from dashboard

🐘 Supabase Dashboard

supabase.com — already using for DB

  • ✅ Table browser — browse, query, edit any table
  • ✅ SQL editor — run ad-hoc queries
  • ✅ Database logs — query performance, errors
  • ✅ Auth users — if using Supabase Auth (currently using Clerk)
  • ✅ API logs — request volume, errors

📊 Supabase + Metabase (optional)

Open-source BI tool, connects to Postgres

  • ✅ Usage dashboards — daily active users, generations, credits
  • ✅ SQL → chart — write a query, get a graph
  • ✅ Scheduled reports — email weekly summaries
  • ⚡ 10-min setup: connect to Supabase Postgres URL

💡 Recommended Approach

✅ Do NOT build — use existing tools

User management → Clerk Dashboard (search users, ban, view sessions)
Payment transactions → Dodo Dashboard (revenue, refunds, subscriptions)
Raw data queries → Supabase Table Editor + SQL Editor

✅ Build a lightweight /admin page (3 screens)

One page, three concerns, ~half a day to build:

1. Overview Dashboard — aggregate metrics at a glance.
Total users, total credits issued, credits spent (all-time + 24h), total generations, generations today, active users (last 7 days).

2. User Lookup — search by email, see full profile.
Credit balance, lifetime credits, generation count, recent transactions, recent creations. Grant credits button.

3. System Status — the existing admin status endpoint.
DB health, webhook health, webhook event log, grant credits form.

⚡ Optional: Add Metabase (free, open-source)

Connect to Supabase Postgres and get drag-and-drop dashboards for:
Daily active users chart · Credit balance distribution · Generation volume over time · Template popularity ranking · Revenue trends from Dodo data (if you sync it)

🤔 Open Questions

  1. Is Supabase's built-in SQL editor enough for ad-hoc queries?
    If yes, you only need the custom /admin page for credit management + user lookup by email.
  2. Do you want Metabase for pretty charts?
    Free, self-hosted or Supabase Marketplace. Connect to same Postgres.
  3. Who gets admin access?
    Currently: anyone with the ADMIN_API_KEY. Could add Clerk org-based auth later.
  4. Do you need a navigation link, or is /admin a secret URL?
    Recommend: not linked from nav. Access via /admin URL + admin key header. Clerk-based admin check optional.
